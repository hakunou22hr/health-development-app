# health-development-app

# 健康開発アプリ

食事写真から食品と量の候補を認識し、利用者が確認した量で栄養を計算するスマートフォン対応アプリです。運動の消費エネルギーと時間の目安、食事・活動の日別記録、7日間の振り返り、JSONバックアップを備えます。

新規リポジトリ名：`health-development-app`。GitHubのリポジトリ名はASCIIで管理し、画面の名前は「健康開発アプリ」です。既存の数学教材リポジトリから独立しています。

## 起動

Node.js 22.9以上。

```sh
npm ci
npm run build
npm start
```

`http://localhost:8787` を開きます。APIキー未設定でも、食品の手動選択・栄養表示からの入力・活動計算・日別記録が使えます。自動認識を模した結果は通常のアプリにはありません。ホームの「サンプルを試す」は、明示した操作確認用サンプルです。

開発は2つのターミナルで `npm run dev:api` と `npm run dev` を実行。ブラウザーは `http://localhost:5173`。Viteが `/api` をローカルのバックエンドへ転送します。

## Google Gemini写真認識を接続する

1. [Google AI Studio](https://aistudio.google.com/apikey) で、課金を有効にしていないプロジェクトのAPIキーを用意します。
2. [公式料金表](https://ai.google.dev/gemini-api/docs/pricing) とAI Studioで、自分のプロジェクト・地域・モデルの無料枠を確認します。
3. `.env.example` を `.env` にコピーし、サーバー側だけに `GEMINI_API_KEY` を設定します。チャット・ソース・GitHubには貼らないでください。`VITE_` から始まる変数にキーを入れると公開されるため禁止です。
4. 課金なしのプロジェクトであることを確認した上で `GEMINI_FREE_PROJECT_CONFIRMED=true` を設定します。未確認・未設定では写真認識を動かしません。
5. `GEMINI_MODEL` を設定します。実装の既定値は確認時の公式料金表で無料枠のある `gemini-3.5-flash-lite`。モデル名・利用可否・無料枠は変更されるため、AI Studioの表示を優先してください。
6. サーバーを再起動します。画面の設定で接続状態を確認し、食事写真を選んで写真送信に同意してから認識します。

無料枠の請求可否をアプリから照会するAPIは実装していません。確認フラグはGoogleの課金状態の保証にはなりません。課金を有効にしたプロジェクトではAPI利用に料金が生じる場合があります。アプリは自動で課金を有効化せず、有料モデルへの切替や失敗時の自動再試行も行いません。Googleの429やアプリの回数上限では手動入力へ戻れます。

回数制限の既定はアプリ全体で1分3回・UTC日付1日20回です。カウンターと接続セッションは単一サーバープロセスのメモリー内にあり、再起動でリセットされます。複数インスタンスでの厳密な上限や永続的な課金防止機能ではありません。

## 写真とプライバシー

- ブラウザーで写真を最大1280pxのJPEGへ変換し、元画像のEXIF位置情報を含めずに送ります。
- 写真認識に送るのは写真と食品候補の指示のみ。体重・過去の記録は送信しません。
- アプリのサーバーは写真をディスクやDBに保存せず、画像・APIキー・認識本文をログ出力しません。
- これはGoogle側の保存や利用まで禁止する仕組みではありません。[Googleの料金・データ利用条件](https://ai.google.dev/gemini-api/docs/pricing) を確認してください。無料枠では入力が製品改善に使用される場合があるため、送信前に画面で説明します。
- 食事・活動はこのブラウザーのlocalStorageに保存。写真は保存・バックアップに含めません。別端末や別URLへ自動同期しません。
- ブラウザーのデータ消去で記録は消えます。設定からJSONを保存し、バックアップを読み込めます。読み込みは現在の記録の置き換えで、確認が必要です。

## 栄養の計算と対応範囲

`shared/foods.mjs` に出典付きの11食品を収録。各食品の調理状態と可食部100gの値を明示し、重量に比例して計算します。カタログ全体の自動同期・全料理対応ではありません。

出典は[文部科学省 食品成分データベース](https://fooddb.mext.go.jp/)（日本食品標準成分表・八訂増補2023年）。写真だけでは油・砂糖・塩・重さを正確に判断できないため、認識後に確認・補正します。未知の食品を既知の食品へ強制的に当てはめず、選び直すかパッケージの栄養表示を入力するまで保存できません。

糖質は `炭水化物−食物繊維` の概算で、「糖類」ではありません。エネルギーは食品成分表または利用者入力の値を使用します。単純な4/9/4換算と一致しない場合があります。栄養表示が1食あたりの場合は100gあたりへ換算して入力します。

## 運動の計算

[2024 Adult Compendium](https://pacompendium.com/) の活動別METsを使用します。

- 活動中の総消費：`METs × 体重kg × 時間h × 1.05`
- 安静時を除く追加分：`(METs−1) × 体重kg × 時間h × 1.05`（初期設定）

同じ計算式を逆算し、指定エネルギーに相当する活動時間を比較します。保存時の体重・計算方法を各運動記録に保持するため、後から設定を変えても過去の値は変わりません。

成人の集団平均に基づく概算で、個人の実測値や推奨運動時間ではありません。子ども・高齢者・運動制限のある人などには一般化できません。食事を帳消しにするような運動指示や病気の診断は行いません。

## 公開するとき

写真認識はGitHub Pages単体では動きません。Nodeサーバーと静的画面を同じHTTPSのURLで提供します。GitHub Pagesなどへ画面だけを置いた場合は、手動入力のみ利用できます。

- サーバーを外部へ公開するときは `HOST=0.0.0.0`、`APP_ORIGIN=https://実際のアプリURL`、推測されにくい `APP_ACCESS_TOKEN` を秘密設定で指定します。
- 画面の設定から接続用パスフレーズを入力します。Gemini APIキーとは別物で、端末の記録には保存しません。
- 接続セッションはHttpOnly・SameSite=StrictのCookie。公開時はSecure属性を付けます。
- HTTPS終端を持つホスティングへDockerfileまたはNodeアプリとして配置できます。ここではホスティング契約・有料リソース作成・一般公開を行っていません。
- 単一利用者向けの最初の版です。複数利用者のサービスへ広げる際は、アカウント認証・永続的な利用制限・監査・利用規約の整備を追加してください。

## 検証

```sh
npm test
npm run build
```

13件の自動テスト：食品の重量換算、未対応食品、栄養表示、METsの計算と逆算、日付・バックアップ、写真の形式・同意、Google送信ペイロード、非食品・不正な応答・上限、認証・Origin・公開時の必須設定。

Chromiumのブラウザー操作では、食事補正・保存・再読み込み、体重による運動記録、日付切替、JSON出力、写真圧縮、認識候補の補正、未対応食品、429時の手動入力、390／820／1440pxの全5画面を確認しています。Google応答をテスト用に差し替えた検証で、実APIによる精度測定ではありません。本番サーバーでも、保存失敗時の入力維持・編集時の重複防止・削除確認・バックアップ復元を確認しています。iOS実機の撮影・Safariは未検証です。

APIキー未設定のため、実際のGemini呼出しは未検証。モデルの利用可否と写真の認識精度はキー設定後に試してください。
